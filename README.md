# 坦克大战 3D · BATTLE CITY 3D

按《坦克大战3D_Agent一次性开发规格书.md》实现的单文件 3D 坦克大战。所有模型、贴图、音效均为程序化生成，无外部美术/音频素材。

## 运行方式

- **直接双击 `battle-city-3d.html`** 即可（已实测 file:// 直开）。
- 首次运行需要联网：从 unpkg 加载 Three.js r160，并从 Google Fonts 加载 `Press Start 2P` / `Noto Sans SC`（字体缺失时自动回退系统字体）。
- 若浏览器不支持 WebGL、或 CDN 不可达，页面会显示明确的错误提示，不会白屏。
- 也可以用本地静态服务器打开（例如 `python -m http.server`），行为一致。

## 实现内容

- **五张内置地图**（逐字符按规格书）+ 第 6 关起随机图（含洪泛连通校验），主题按关轮换：白昼 / 黄昏 / 冰原 / 夜战。
- **四类敌车**：基础 / 快速 / 强化 / 装甲（4 血、按血量变色），差异化程序化模型、AI 决策（直行 / 朝基地 / 朝玩家 / 随机，受阻重判，同轴射击）。
- **玩法**：砖墙 2×1 逐格破坏、钢墙仅 3 级火力可破、水挡车不挡弹、树冠遮挡、冰面打滑、子弹互消、坦克互撞阻挡、鹰徽被毁即败。
- **六种道具**：星星 / 手雷 / 头盔 / 定时器 / 铁锹 / 坦克，携带者红白闪烁、击毁必掉；铁锹到期复原、冻结按秒解除。
- **完整流程**：LOADING → TITLE → STAGE 演出 → PLAYING ⇄ PAUSED → TALLY → 下一关；鹰毁/生命耗尽 → GAME OVER → TITLE。
- **表现**：程序化坦克/鹰/道具模型，Canvas 贴图，动态水面，Bloom + CRT 扫描线 + FXAA，四主题光影，震屏、慢动作、爆炸/碎片/护盾/水花/浮分等池化特效。
- **音频**：Web Audio 全合成，21 种 SFX、战斗/标题 BGM（附录 B 乐谱）、引擎循环、暂停挂起、静音与三路音量。
- **UI/HUD**：分数/最高分/火力/20 个敌方图标/道具倒计时环/生命/关卡旗标，设置项全部实时生效并持久化。

## 实测记录（如实标注）

测试环境：Windows + Chromium（Playwright 无头，SwiftShader 软件渲染），1280×800 视口。

已实际执行并通过：

- `node --check` 对装配后模块脚本语法检查通过；禁用词/占位串扫描为空，`setInterval` 仅存在于音频 BGM 调度。
- **file:// 直开**：LOADING → TITLE → PLAYING 全流程通过。
- **控制台**：正常游戏路径 `console.error = 0`、`console.warn = 0`、无未捕获异常；CDN 阻断测试中出现的网络错误为预期。
- **机制**：20 台队列与携带者位 4/11/17/20、坦克互撞阻挡、子弹击杀/计分、装甲 4 血、钢墙仅 3 级火力可破、六种道具全部生效、护盾吸收敌弹、冻结/铁锹到期恢复、携带者掉落、20000 分奖命、子弹互消、TALLY → 下一关、鹰毁 → GAME OVER、生命耗尽 → GAME OVER、1–8 关地图校验、主题 3/4/5 切换。
- **健壮性**：失焦自动暂停、窗口缩放适配、静音切换、HI-SCORE 与设置刷新后保留、CDN 缺失错误页。
- 截图与报告：`build/devtest/out/`（含 `pw-report.json`、`pw-extra.json`）。

尚未验证/未覆盖：

- **音频听感**：仅验证 AudioContext 就绪、全部音效/BGM 调用无异常；当前测试环境为静音无头浏览器，未做人工听感与声压验收。
- **真实 GPU 帧率**：测试使用 SwiftShader 软件渲染，帧率明显低于真实显卡，不能代表实际性能；未完成规格书要求的“连续 10 分钟无 GC 卡顿”长时观测（已做多轮短时压力与池化检查）。
- **手柄**：规格书标注“可选”，本作未实现手柄。
- **数值手感**：全部参数按规格书取值，未做额外调优。
- 依赖 CDN；完全离线运行需自行将 Three.js 与字体改为本地文件（当前按规格书要求使用 CDN）。

## 与规格书的偏离

- §8 的“常态 draw call <120”未达成：高画质、5 车 + 爆炸 + 道具场景实测约 **204 draw calls**（含阴影渲染 pass）、约 2.1 万三角形。已使用 InstancedMesh、材质合并、对象池等手段，但未继续做网格合并/烘焙优化。
- §7 的“手柄支持”在规格书中标为可选，本作未实现。
